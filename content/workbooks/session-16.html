Session 16: Block Programming & Algorithms

Until today, you have used software that other people built (Word, Excel, PowerPoint, Web Browsers). Today, you step across the line from being a technology consumer to becoming a technology creator: you will write your first computer program!

1. Plain Talk: The Kelewele Recipe (What is an Algorithm?)

Computers are lightning fast, but they are as dumb as a stone—they cannot guess what you want. They can only follow an Algorithm: a step-by-step list of clear, ordered instructions to accomplish a specific goal.

Think about making spicy fried plantain (Kelewele):

Figure 16.0: An Algorithm is a step-by-step sequence. The computer executes steps from left to right, top to bottom.

2. Why "Block-Based" Coding?

❌ TEXT-BASED CODE (Frustrating for Beginners)

Typing code by hand in languages like Python or C++. If you forget a single semicolon (;) or comma, the entire program crashes with a confusing error message.

✅ BLOCK-BASED CODE (Visual & Fun!)

In Scratch, instructions are shaped like colorful puzzle pieces. You drag and snap them together. If two blocks don't make logical sense, they physically refuse to snap together!

2. Essential Scratch Vocabulary

  • Sprite: A character, person, animal, or object on the stage that you can control with code blocks.
  • Backdrop: The background scenery picture behind your sprites on the stage (e.g. a classroom, forest, or soccer field).
  • Script: A stack of two or more code blocks snapped together that run in order from top to bottom.
  • Green Flag: The "GO" trigger button that starts your program.
Block Types & The Event Spark
Session 16 • Page 3

1. Why Blocks Look Like Puzzle Pieces

Look closely at how Scratch blocks are built. They have notches on the top and bumps on the bottom. This guarantees that blocks connect only in ways that make logical sense to the computer:

Figure 16.2: Anatomy of Scratch blocks. Hat blocks start scripts; Stack blocks carry out the actions.

2. The Golden Rule of Events: The Spark Plug

⚡ NO EVENT = NO ACTION!
If you snap together 10 motion blocks but forget to put a yellow Event Hat Block (like when green flag clicked) at the very top, the computer will sit completely still. The Event block is the electrical spark plug that ignites the code engine!

3. Core Motion Commands

Block Name What It Does Real-World Result
move (10) steps Glides the sprite forward in the direction it is currently facing. Walking forward 10 tiny screen pixels.
turn clockwise (15) deg Rotates the sprite to its right like turning a steering wheel. Pivots right by 15 degrees.
say [Words] for (2) secs Displays a cartoon speech bubble above the sprite's head. Character speaks dialogue out loud.
The Stage & The X/Y Coordinate Secret
Session 16 • Page 4

1. Where is My Sprite Standing?

To tell your character where to jump, walk, or appear on the stage, the computer uses a mathematical grid called the X and Y Coordinate Plane. This is just like finding a cell coordinate in a spreadsheet!

Figure 16.3: The Scratch Stage Grid. X controls horizontal movement (left/right); Y controls vertical height (up/down).

2. Coordinate Rules in Plain Language

↔️ X IS HORIZONTAL (Side to Side)

• Positive X numbers (+10, +100) move the sprite to the RIGHT.

• Negative X numbers (-10, -100) move the sprite to the LEFT.

↕️ Y IS VERTICAL (Up and Down)

• Positive Y numbers (+10, +100) push the sprite UP into the air.

• Negative Y numbers (-10, -100) drop the sprite DOWN to the ground.

3. Panic Button / Troubleshooting

🚨 MY SPRITE RAN OFF THE SCREEN AND DISAPPEARED!
If you tell a sprite to move 1,000 steps, it walks straight off the edge of the screen!

How to rescue it in 1 second:
  1. Look at the Motion palette (blue). Find the block: go to x: (0) y: (0).
  2. Click on that block once right inside the palette!
  3. Your sprite instantly snaps straight back to the dead center of the stage!
